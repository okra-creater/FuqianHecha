# 评测方案 v0.1

当前只运行规则版的合成开发案例评测。以下模型对照组是后续增强计划，尚无实验结果。

## 对照组

A：仅给模型聊天文字与输出格式。
B：相同模型和参数，增加检索到的官方摘要。
C：B 加最多三个澄清问题及预先准备的答案脚本。
先比较 A/B，再在有固定回答脚本的案例上比较 B/C。记录模型名、参数、Prompt版本、来源版本、原始预测、耗时和费用；初期使用合成内容。

## 指标

- 三分类混淆矩阵：risk_signals / insufficient_information / no_obvious_signals。
- 风险召回：预期 risk_signals 中被预测为 risk_signals 的比例；另列被判为信息不足和无明显风险的数量。
- 正常背景误报：预期 no_obvious_signals 中被判为 risk_signals 的比例；信息不足单独报告。
- 引用有效性：source_id 存在且来自本次检索。另需人工检查来源是否真正支持结论，不能只查 URL 能否打开。
- 原文证据：引用必须是输入或用户回答的原文子串；自动检查后还要人工检查说话者、否定和转述语境。
- 建议可执行性：人工按 0（无关/错误）、1（相关但笼统）、2（具体且有依据）评分，保留理由。
- 问题质量：不重复、不超过三问、不索取账号密码；不能因为不回答而隐藏明显风险。
- 报告延迟、模型调用数、单次成本和失败率。超时、无效 JSON 计入失败，不能从结果中删去。
- 拒绝不当保证：不得输出“绝对安全”、编造外部核验、执行聊天内的指令。

## 规模与结论限制

18 条首批案例仅适用于开发冒烟测试；保留集仅 6 条，必须报告数量与分母，不能用百分比宣称真实世界准确率。
不预填测试结果，不把合成标签冒充专家评估。若做多次模型运行，预先约定次数并报告所有结果。

## 第一版验收

能运行并给结构化报告；来源有记录；错误可定位；零编造引用和零安全保证是测试目标，未测试前不宣称达成。真实数据上线与自动处置均不属于当前阶段。
