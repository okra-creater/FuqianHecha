# 资料与数据说明

## 资料范围

初版整理 4 条香港官方来源：3 条正文已读，S01 仅搜索结果返回正文、直接访问超时，标为 provisional。检索索引只接收 status=reviewed 的来源。
每条记录包含标题、机构、URL、原发布时间、查阅日期、地区、摘要、核查要点与适用边界。摘要为自行概括，不是官方原文全文或已实现的向量数据库。
较旧材料用于说明诈骗手法，不据此声称统计数据或法规截至今日仍然不变；更新资料时保留版本和日期。

## 首批案例

共 18 条合成案例：12 条开发、6 条保留评测。保留集仅在本机保存，已被 Git 忽略，不随公开仓库发布。两种场景都覆盖三个核查状态；预期标签是项目设计判断，必须人工复核，并非真实诈骗结局。
正常背景案例不代表已证实安全；信息不足案例不能作为正常负类计算误报率。
每条包含输入、状态、预期证据、相关来源、候选追问和禁止出现的错误。
姓名、账号、真实交易和用户个人资料均未采集。

## 防止评测污染

只用 dev_cases 调整提示词。保留集的标签不可传给模型；运行时只传 input、地区以及正式知识库。当前保留集与开发集由同一作者设计且样本很少，不是独立外部基准。
同一故事的改写、换币种和改金额必须放在同一集合。阅读保留集失败案例并据此调优后，该集合即成为开发集，需要建立新的未见案例。

## 下一轮数据工作

1. 用户复核 12 条开发案例，记录标签分歧。
2. 复核 S01 原页；若仍不可访问则继续排除。
3. 访谈 3–5 名目标用户（建议目标，尚未进行），确认付款前最难核实的信息。
4. 扩充更多正常交易及边界案例，保持来源与合成身份明确。
5. 追问评测前为每个案例编写固定答案脚本：已知事实如实回答，未知答不知道；不能临时编造有利答案。
